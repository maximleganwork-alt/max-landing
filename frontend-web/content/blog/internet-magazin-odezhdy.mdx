Конверсия в e-commerce одежды — функция десятков мелочей. Карточка товара без размерной сетки убивает 5-10% продаж. Невозможность отфильтровать по размеру — ещё столько же. Разберём, какие элементы воронки обязательны и почему.

## Каталог: фильтры и поиск

Главное правило: пользователь не должен листать. Если в категории больше 30 товаров — нужны фильтры. Минимум: размер, цвет, цена, бренд, материал, сезон. В идеале — сохранение состояния фильтров в URL (через query-параметры), чтобы можно было поделиться ссылкой.

На Next.js это решается через `useSearchParams` и серверный рендер с ISR: фильтрованная страница `/catalog?size=M&color=black` кешируется и отдаётся за 50-100мс. Поиск с автоподсказками — отдельная история: pgvector или Meilisearch для семантического поиска по описанию даёт лучший UX, чем чистый LIKE по названию.

## Карточка товара

Карточка — это место, где принимается решение о покупке. Что обязательно: 6-10 фото (разные ракурсы плюс деталь, плюс на модели с указанием её роста), видео 15-30 секунд, размерная сетка с возможностью сравнить с другим брендом, состав и уход, наличие по размерам, отзывы с фотографиями покупателей.

Размерная сетка — отдельная боль. Универсального решения нет: разные бренды одного размера сильно отличаются. Что работает: «у наших джинсов размер L соответствует 32 талии», плюс калькулятор по росту/весу/обхвату.

## Корзина и оформление

Корзина должна быть простой. Один экран с товарами, промокодом, доставкой, оплатой. Оформление в один шаг (если возможно) или максимум 3 шага: контакты — доставка — оплата.

Гость-чекаут обязателен. Принудительная регистрация снижает конверсию на 15-25%. Регистрация — опционально, через галочку «сохранить данные для следующих покупок». СБП — обязательная опция оплаты в РФ. ЮKassa, Тинькофф Касса, CloudPayments — выбор в основном по комиссиям и условиям возвратов.

## Доставка и пункты выдачи

Интеграция с СДЭК, Boxberry, Яндекс.Доставкой, Почтой России — это не «фича», это базовая функция. Пользователь должен видеть пункты выдачи на карте, выбрать ближайший, увидеть точную стоимость и срок.

API всех этих сервисов задокументированы. Для CDEK и Boxberry есть готовые виджеты, но кастомная реализация даёт лучший UX и контроль. Postgres хранит выбор пользователя, чтобы при следующем заказе он подставился автоматически.

## Возвраты и обмены

В одежде возвраты — норма (15-30% по размеру), а не аномалия. Личный кабинет должен поддерживать оформление возврата в 3 клика: выбрать заказ, выбрать товар, причина возврата. Дальше — этикетка для отправки в ПВЗ, статус обработки, возврат денег.

Без удобного процесса возврата пользователи не делают повторных заказов. С удобным — LTV вырастает в 1.5-2 раза.

## Аналитика и оптимизация

GA4 + Yandex Metrika с настроенным e-commerce: события `view_item`, `add_to_cart`, `begin_checkout`, `purchase`. Без этого вы не узнаете, на каком шаге воронки теряете клиентов.

Микро-конверсии тоже важны: добавление в избранное, открытие размерной сетки, клик по «вопрос о товаре». Это даёт более ранние сигналы для оптимизации, чем смотреть только на финальные покупки.

## Итого

Интернет-магазин одежды — это десятки мелочей, каждая из которых режет 1-3% конверсии. Размерная сетка, гость-чекаут, СБП, удобные возвраты, фильтры в URL — это не «крутые фичи», это база. Бюджет — от 1.5 миллионов за MVP до 5-8 миллионов за полноценный магазин с админкой, интеграциями и мобильным приложением. Срок — 3-6 месяцев.
