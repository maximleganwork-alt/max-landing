Выбор платёжного шлюза в РФ — это компромисс между комиссией, удобством интеграции и поддержкой нужных сценариев. Разберём актуальные опции 2026 года и подскажем, что выбрать в зависимости от типа бизнеса.

## Основные игроки

**ЮKassa** (бывшая Яндекс.Касса). Самый популярный шлюз для интернет-магазинов и SaaS в РФ. Поддерживает карты, СБП, *Mir Pay*, рекуррентные платежи, рассрочки. Тарифы — *от 2.8% за транзакцию*, для малого бизнеса есть фиксированная стоимость подключения.

**Тинькофф Касса**. Сильная альтернатива с фокусом на быстрое подключение и удобную админку. Поддержка СБП, B2B-эквайринг, рекурренты. Комиссия сравнима с ЮKassa.

**Сбер AcquiringHQ / Sber Pay**. Бренд и охват крупного банка. Подходит для крупного e-commerce; для МСБ — несколько громоздкое подключение.

**CloudPayments**. Удобный для веб-разработчиков шлюз с понятным API. Особенно хорош для подписочных моделей и SaaS.

**ЮMoney** (физлицам), **Robokassa** — для микропроектов и фриланс-задач.

**СБП** (Система быстрых платежей) — отдельная история: оплата по QR-коду через банк пользователя, комиссия **0.4–0.7%**, моментальное зачисление. Подключается через большинство шлюзов или напрямую через банк-эквайер.

## Как выбирать

### По комиссии

Для типового интернет-магазина:

- Карты: **2.0–3.0%**.
- СБП: **0.4–0.7%**.
- Рассрочка через банк: **3–7%** (платит магазин или клиент).
- B2B-эквайринг: **1.0–1.8%**.

При обороте от **1 млн ₽/мес** имеет смысл договориться об индивидуальном тарифе.

### По типу бизнеса

- **Интернет-магазин**: ЮKassa или Тинькофф + обязательно СБП.
- **SaaS с подписками**: CloudPayments или ЮKassa с поддержкой рекуррентов.
- **B2B-сервис**: Тинькофф или Сбер для безналичных + СБП C2B для физлиц.
- **Услуги, мелкий e-com**: ЮKassa с подключением через личный кабинет.

## Технические аспекты интеграции

Все современные шлюзы работают через одинаковую модель:

1. Сайт создаёт *платёжную сессию* через REST API шлюза.
2. Получает URL для оплаты (или embedded-форму).
3. Перенаправляет пользователя на оплату.
4. Получает *webhook* со статусом платежа.
5. Подтверждает или отменяет заказ в своей системе.

**Подводные камни**:

- Webhook-и должны быть *идемпотентными* — один платёж может прилететь дважды.
- Подпись webhook'а проверяется обязательно — иначе можно подделать «успешную оплату».
- Не доверяйте редиректу пользователя как единственному источнику истины — он может закрыть вкладку до возврата.
- Логируйте все события с *idempotency key*; это спасёт при разборе спорных платежей.

## Подписки и рекурренты

Для SaaS критична поддержка автосписаний. ЮKassa, Тинькофф и CloudPayments умеют сохранять токен карты и списывать по расписанию. Не реализуйте автосписания самостоятельно — это нарушение PCI DSS и требований шлюза.

Особенности:

- Согласие на регулярные списания должно быть **явным** в интерфейсе.
- Уведомление пользователя за 3 дня до списания снижает chargeback'и.
- При неудачном списании имейте *retry policy* (3 попытки за 7 дней).

## Что часто забывают

- Возвраты — отдельный API, тестируйте на тестовой среде.
- Чек по 54-ФЗ — каждая онлайн-оплата физлица генерирует чек через ОФД.
- Лимит на сумму без 3DS — некоторые карты блокируют без подтверждения.
- Поддержка *Mir Pay* и *Apple Pay/Google Pay* через виртуальные карты — пользователи всё ещё им пользуются.

## Что в сухом остатке

Дефолт для МСБ — **ЮKassa или Тинькофф** + обязательно **СБП**. Для SaaS с подписками — **CloudPayments** или ЮKassa. Для крупного e-commerce — Сбер или прямой эквайринг банка. Бюджет интеграции — **от 80 000 ₽** за стандартное подключение, **от 200 000 ₽** для подписочной модели с биллингом и личным кабинетом.
