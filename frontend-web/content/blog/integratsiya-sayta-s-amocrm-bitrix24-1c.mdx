Интеграция сайта с CRM и 1С — это не «отправить заявку через webhook». Это про надёжный обмен данными в обе стороны: лиды, сделки, контакты, остатки, цены, заказы, статусы. Чем больше точек обмена, тем больше места для ошибок — и тем важнее проектировать интеграцию по правилам.

## Уровни интеграции

**Базовый**: сайт отправляет лида в CRM по REST или webhook. Сроки — **2–5 дней**. Подходит для лендингов, форм заявки, простых корпоративных сайтов.

**Средний**: двусторонний обмен — CRM отдаёт статусы заявок в личный кабинет, обновляет цены и остатки в каталоге. Сроки — **2–4 недели**. Нужен для интернет-магазинов и B2B-порталов.

**Продвинутый**: сайт является источником истины по части данных, 1С и CRM синхронизируются через очередь сообщений и систему идемпотентных событий. Сроки — **от 6 недель**. Нужен для сложных продуктов с большим оборотом.

## Интеграция с amoCRM

У amoCRM есть стабильный *REST API v4* с OAuth 2.0. Стандартный сценарий — POST лида с UTM-метками, привязка к воронке, автоматическое создание контакта и сделки. Для двустороннего обмена используются *webhooks* — amoCRM присылает события на ваш URL, бэкенд обновляет статусы в личном кабинете.

Подводные камни:

1. Лимит **7 запросов/сек** на аккаунт — при пиковой нагрузке нужна очередь.
2. Срок жизни access-токена — 1 день; refresh-токен ротируется при каждом обновлении.
3. Кастомные поля имеют числовые ID, которые меняются между средами — нужны отдельные конфиги для dev/prod.

## Интеграция с Bitrix24

Bitrix24 даёт **REST API** и протокол **webhooks** двух типов: входящие (вы шлёте в Bitrix) и исходящие (Bitrix шлёт вам). Для интеграции с интернет-магазином есть отдельный механизм *обмена с 1С* — через стандартный CommerceML.

## Интеграция с 1С

С 1С работают через три механизма:

- **CommerceML** — стандартный обмен товарами и заказами. Хорош, когда сайт — типичный интернет-магазин.
- **OData** — REST-интерфейс к произвольным конфигурациям. Подходит для нетипового обмена.
- **HTTP-сервисы** на стороне 1С — программисты на стороне клиента пишут точечные методы. Самый гибкий вариант.

Реалистичный срок интеграции с 1С — **от 3 недель**, если конфигурация типовая, и **6–10 недель**, если она сильно доработана. Главное правило: 1С никогда не делает запросы напрямую в БД сайта — только через слой API на бэкенде с валидацией и логами.

## Типовые ошибки

- Синхронизация без *идемпотентности*: один и тот же заказ создаётся дважды при ретрае.
- Отсутствие очереди (например, на Redis или RabbitMQ): пиковая нагрузка ложит интеграцию.
- Хранение секретов в коде вместо переменных окружения.
- Логирование без маскирования ПДн — нарушение 152-ФЗ.
- Один монолитный «обменник» вместо отдельных сервисов под каждую систему.

## Что в сухом остатке

Хорошая интеграция — это очередь сообщений, идемпотентность, логирование, мониторинг и понятный rollback при ошибках. Срок зависит не от объёма данных, а от качества API на той стороне. Бюджет реалистичной интеграции — **от 80 000 ₽** для базовой и **от 350 000 ₽** для двустороннего обмена с 1С.
