> **Назначение документа:** этот файл — финальное ТЗ для Claude Code. Все требования зафиксированы однозначно. Где встречается **\[плейсхолдер\]** — подставлены условные данные, которые заказчик заменит на реальные после сдачи проекта (название, домен, токены, реквизиты).

## 1. О проекте

Одностраничный продающий лендинг (Single Page Landing) для студии разработки ботов под российский мессенджер **MAX** (национальный мессенджер от VK с 75+ млн пользователей, обязательно предустанавливаемый на смартфонах в РФ).

**Основная цель:** генерация B2B-заявок на разработку ботов, мини-приложений и AI-интеграций внутри MAX.

**Целевая аудитория:** руководители бизнеса, маркетологи, ИТ-директора компаний от SMB до Enterprise, ищущие подрядчика по разработке ботов для MAX.

### 1.1. Ключевые метрики успеха

- Конверсия в заявку (отправка формы): целевое значение ≥ 3%.
- Lighthouse Score: ≥ 95 в Performance, Accessibility, Best Practices, SEO.
- Core Web Vitals: все «зелёные» (LCP ≤ 2.5с, INP ≤ 200мс, CLS ≤ 0.1).
- Топ-10 в Яндексе по основным ключевым запросам в течение 3–6 мес. после индексации.

## 2. Технологический стек

### 2.1. Frontend

- **Next.js 15+** (App Router, Server Components где возможно, SSG для лендинга).
- **TypeScript** (строгий режим).
- **Tailwind CSS 3.4+** (с CSS-переменными для тем).
- **Framer Motion 11+** (анимации).
- **React Hook Form** + **Zod** (валидация форм).
- **next/font** (Inter Variable, локально, с поддержкой кириллицы).
- **next-themes** (переключатель тем light/dark с сохранением в localStorage).
- **lucide-react** (иконки, лёгкий tree-shaking).

### 2.2. Backend

- **Go 1.22+** (отдельный микросервис для приёма заявок).
- Стандартная библиотека `net/http` + минимум зависимостей.
- Зависимости: `github.com/joho/godotenv` (env), `golang.org/x/time/rate` (rate-limit).
- Один эндпоинт `POST /api/lead` — приём, валидация, проверка капчи, отправка в Telegram.

### 2.3. Архитектура запросов

```
[Браузер] → POST /api/lead (Next.js API Route, proxy)
              → POST http://go-service:8080/api/lead (Go service)
                  → POST https://smartcaptcha.yandexcloud.net/validate (verify)
                  → POST https://api.telegram.org/bot{TOKEN}/sendMessage
              ← 200 OK { "ok": true }
            ← 200 OK { "ok": true }
[Toast: «Заявка принята»] + ym('reachGoal', 'form_submit_success')
```

Next.js-роут `/api/lead` нужен как прокси, чтобы:
- скрыть URL Go-сервиса от клиента,
- дополнительно валидировать на сервере Next,
- избежать CORS-проблем при деплое.

## 3. Дизайн-система

Современный, корпоративный, конверсионный стиль. Никаких «AI-эстетик», лишних теней, толстых градиентов и неонов. Чистая типографика, осмысленный воздух, спокойные акценты в фирменном синем.

### 3.1. Цветовая палитра

Фирменные цвета MAX — сине-голубая гамма (логотип-облачко). Палитра подобрана нативно к бренду MAX без копирования айдентики.

Палитра задаётся через CSS-переменные в `globals.css` и подключается в `tailwind.config.ts` через `theme.extend.colors`.

#### Правила использования

- Основной фон секций чередуется: `--bg` → `--bg-subtle` → `--bg` для визуального ритма.
- Карточки на `--bg-card` с границей `1px solid --border`. **Запрещены** массивные `box-shadow`. Допустима только тонкая `0 1px 2px rgba(0,0,0,0.04)` в светлой теме.
- В тёмной теме — без теней, разделение через `--border` и `--bg-elevated`.
- Кнопка primary: фон `--primary`, hover — `--primary-hover`, плавный transition 150мс.
- Текст на цветных блоках: `--primary-fg`.

### 3.2. Типографика

- **Шрифт:** Inter Variable (через `next/font/google` или локально). Кириллица обязательна.
- **Запасной стек:** `'Inter', system-ui, -apple-system, 'Segoe UI', Roboto, sans-serif`.

#### Шкала размеров

| Класс | Размер | Line height | Use |
|---|---|---|---|
| `text-display` | clamp(2.5rem, 5vw, 4.5rem) | 1.05 | H1 в Hero |
| `text-h1` | clamp(2rem, 4vw, 3rem) | 1.1 | Заголовки секций |
| `text-h2` | clamp(1.5rem, 3vw, 2rem) | 1.2 | Подзаголовки |
| `text-h3` | 1.25rem | 1.3 | Заголовки карточек |
| `text-body-lg` | 1.125rem | 1.6 | Лиды |
| `text-body` | 1rem | 1.6 | Основной текст |
| `text-body-sm` | 0.875rem | 1.5 | Caption, подписи |
| `text-caption` | 0.75rem | 1.4 | Юр. примечания, метки |

#### Веса
- 400 (regular) — основной текст
- 500 (medium) — кнопки, метки, нав
- 600 (semibold) — H3, важные акценты
- 700 (bold) — H1, H2, display

Заголовки — с отрицательным `letter-spacing: -0.02em` для display и `-0.015em` для h1/h2. Body — без изменений tracking.

### 3.3. Сетка и spacing

- Контейнер: `max-width: 1200px`, padding по бокам `24px` (mobile) / `40px` (≥768px).
- Сетка секций: 12 колонок, gap `24px` (mobile) / `32px` (desktop).
- Вертикальные отступы между секциями: `80px` (mobile) / `120px` (desktop).
- Tailwind: использовать встроенную spacing-шкалу (`4`, `6`, `8`, `12`, `16`, `20`, `24`).

### 3.4. Радиусы и обводки

- `--radius-sm`: 8px (input, small cards)
- `--radius`: 12px (карточки, кнопки)
- `--radius-lg`: 16px (крупные карточки, модалки)
- `--radius-xl`: 24px (hero-визуал)
- Все интерактивные элементы — `transition: all 150ms ease`.
- Focus ring: `2px solid var(--ring)` + `outline-offset: 2px`. **Никогда** не убирать focus state, только стилизовать.

### 3.5. Запреты по визуалу

- Нет `box-shadow` больше `0 4px 12px rgba(0,0,0,0.06)`.
- Нет неоновых glow-эффектов.
- Нет градиентов больше чем на 20% площади экрана.
- Нет «глассморфизма» (`backdrop-filter: blur` допустим только в Header при скролле).
- Нет stock-3D рендеров и AI-сгенерированных «персонажей».

- Адаптация под темы: светлая тема — белый фон экрана, серые баблы пользователя, фирменно-голубые баблы бота. Тёмная — тёмный экран, нейтральные баблы пользователя, голубые баблы бота.
- Лёгкий «парящий» эффект (Framer Motion `animate={{ y: [0, -8, 0] }}` с infinite repeat, длительность 6с).
- Сзади — мягкий радиальный градиент `--accent-soft` (без блюра 100px и больше).

## 6. UI-компоненты (sr-only описание)

Каждый компонент в `components/ui/` должен:
- быть полностью типизирован (TypeScript),
- поддерживать `forwardRef`,
- принимать `className` и мерджить через `cn()` утилиту (`clsx` + `tailwind-merge`),
- иметь корректные ARIA-атрибуты,
- работать в обеих темах.

### 6.1. Button

Варианты: `primary`, `outline`, `ghost`, `link`. Размеры: `sm`, `md`, `lg`. Состояния: `default`, `hover`, `focus-visible`, `disabled`, `loading`.

### 6.2. Input / Textarea

С floating label. Состояния: `idle`, `focus`, `error`, `disabled`. Сообщение об ошибке — `aria-describedby`.

### 6.3. Checkbox

Кастомный с фирменной галочкой. Поддержка `indeterminate` не нужна. ARIA-checked.

### 6.4. Modal

На основе `<dialog>` или Headless-паттерна. Закрытие по Escape, клику на оверлей, кнопке `×`. Trap focus внутри модалки. На mobile — bottom sheet (выдвигается снизу).

### 6.5. Toast

Контейнер в правом нижнем углу (mobile — снизу по центру). Стек до 3 одновременно. Автоисчезновение через 6с (можно навести — пауза). Варианты: `success`, `error`, `info`.

### 6.6. ThemeToggle

Иконка `Sun` ↔ `Moon`. Плавный crossfade 200мс. Использовать `next-themes`. По умолчанию `system`, при первом клике переключается на противоположную текущей.

### 6.7. Accordion (для FAQ)

Управляемый/неуправляемый. По умолчанию все закрыты. Анимация раскрытия — `framer-motion` `<AnimatePresence>` + `<motion.div>` с `height: auto`.

## 7. Форма заявки — спецификация

### 7.1. Frontend-валидация (Zod)

```ts
const leadSchema = z.object({
  name: z.string().min(2, 'Минимум 2 символа').max(100),
  contact: z.string().refine(
    (v) => /^[\+\d\s\-\(\)]{10,20}$/.test(v) || /^@[\w\d_]{4,32}$/.test(v),
    'Укажите телефон в международном формате или @ник'
  ),
  message: z.string().max(1000).optional(),
  tariff: z.enum(['starter', 'business', 'enterprise', '']).optional(),
  consent: z.literal(true, { errorMap: () => ({ message: 'Требуется согласие' }) }),
  captchaToken: z.string().min(1),
  // honeypot — невидимое поле, не должно быть заполнено
  website: z.string().max(0).optional(),
});
```

### 7.2. Frontend-flow

1. Валидация формы Zod-схемой.
2. Получение токена SmartCaptcha (invisible).
3. POST на `/api/lead` (Next.js route).
4. Next.js route:
   - повторная валидация Zod,
   - проверка honeypot (если заполнен — `return 200 OK`, ничего не делая),
   - проксирование в Go-сервис (по `BACKEND_URL`).
5. Обработка ответа:
   - 200 → toast success + метрика + reset формы;
   - 429 → toast rate-limit;
   - 4xx/5xx → toast error.

### 7.3. Backend (Go) — спецификация эндпоинта

**`POST /api/lead`**

**Request body** (JSON):
```json
{
  "name": "Иван",
  "contact": "+7 999 123 45 67",
  "message": "Нужен бот для приёма заявок",
  "tariff": "business",
  "captchaToken": "...",
  "website": ""
}
```

**Логика обработки:**

1. Rate limit по IP: 5 запросов / 1 минута. Если превышено — `429 Too Many Requests`.
2. Honeypot: если `website` непустое — вернуть 200 без действий.
3. Валидация полей (повтор фронтовых правил).
4. Проверка SmartCaptcha:
   ```
   POST https://smartcaptcha.yandexcloud.net/validate
   {
     "secret": "<SMARTCAPTCHA_SERVER_KEY>",
     "token": "<captchaToken>",
     "ip": "<client IP>"
   }
   → { "status": "ok", ... }
   ```
   Если `status != "ok"` — `400 Bad Request`.
5. Формирование сообщения в Telegram (Markdown):
   ```
   *🆕 Новая заявка с лендинга*
   
   *Имя:* Иван
   *Контакт:* +7 999 123 45 67
   *Тариф:* Бизнес
   
   *Задача:*
   Нужен бот для приёма заявок
   
   _IP: 1.2.3.4 · UA: Chrome 120_
   ```
6. Отправка:
   ```
   POST https://api.telegram.org/bot<TOKEN>/sendMessage
   { "chat_id": "<CHAT_ID>", "text": "...", "parse_mode": "Markdown" }
   ```
7. Ответ клиенту: `200 { "ok": true }` или `5xx` при ошибке Telegram (но не блокировать пользователя — заявку всё равно записать в лог-файл / stdout для ручного подбора).

**Response (success):** `200 { "ok": true }`
**Response (validation):** `400 { "ok": false, "error": "validation" }`
**Response (rate limit):** `429 { "ok": false, "error": "rate_limit" }`
**Response (server):** `500 { "ok": false, "error": "internal" }`

### 7.4. Защита от спама (резюме)

| Слой | Реализация |
|---|---|
| Honeypot | Поле `website`, скрытое CSS. Заполнено → silent 200. |
| SmartCaptcha | Invisible widget на фронте, серверная проверка по API Яндекса. |
| Rate limit | По IP: 5 запросов/мин (`golang.org/x/time/rate`). |

## 8. Аналитика

### 8.1. Яндекс.Метрика

- Установка через `next/script` с `strategy="afterInteractive"`.
- ID счётчика — в `NEXT_PUBLIC_YANDEX_METRIKA_ID`.

**Поведение:**

## 11. Анимации (Framer Motion)

Минимально и со вкусом. Никаких «прыгающих» элементов, спин-эффектов, parallax-перегрузов.

### 11.1. Глобальные правила

- Все анимации появления — `opacity: 0 → 1` + `translateY: 16px → 0`, длительность `400мс`, easing `ease-out`.
- Триггер — попадание в viewport через `useInView` с `once: true`, `margin: "-10% 0px"`.
- Для блоков с несколькими элементами — `staggerChildren: 0.08`.
- `useReducedMotion()` — для всех анимаций, при `prefers-reduced-motion: reduce` отключаем `translateY`, оставляем только `opacity`.

### 11.2. Конкретные места

| Где | Что |
|---|---|
| Hero | Текст + кнопки — fade+up по очереди (stagger 0.1). Phone-mockup — лёгкий бесконечный y-floating (`[0, -8, 0]`, 6с). Чат-баблы — последовательное появление с stagger 0.4. |
| Цифры в стрипе | Counter-up от 0 до целевого (5, 50, 30) при попадании в viewport. Для `24/7` — без анимации, просто fade. |
| Карточки секций | Fade+up при scroll. |
| Hover на карточках | `translateY: -2px`, transition 200мс. |
| Аккордеон FAQ | `height: auto` через AnimatePresence + `<motion.div>`. Иконка `+` → rotate 45deg. |
| Theme toggle | Crossfade 200мс между Sun/Moon. |
| Modal открытие | Backdrop fade 200мс, content `scale: 0.96 → 1` + opacity, 250мс. |
| Toast | Slide-in с правой стороны (или снизу на mobile), exit — обратно. |
| Sticky CTA | Slide-up 200мс при появлении. |
